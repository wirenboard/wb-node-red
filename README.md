# wb-node-red

Установка одной командой — `apt install wb-node-red` — чтобы запустить
[Node-RED](https://nodered.org/) на контроллере
[Wiren Board](https://wirenboard.com/) как системный сервис, готовый к работе
из коробки.

## Что вы получаете

- **Node-RED как сервис**, запущенный отдельным непривилегированным
  systemd-сервисом (`wb-node-red.service`). Node.js берётся из дистрибутива
  (`Depends: nodejs`), поэтому его обновления безопасности приходят из
  репозитория Wiren Board / Debian.
- **Дефолтный flow**, уже подключённый к локальному MQTT-брокеру
  (`127.0.0.1:1883`) и дереву устройств (`/devices/#`) — открываете редактор и
  сразу видите живые данные контроллера. Работа с Wiren Board — это штатные
  MQTT-ноды и конвенции топиков (`/devices/<dev>/controls/<ctl>`, запись через
  `.../on`); во flow есть готовый пример записи — включение зуммера
  контроллера. Палитру сообщества `node-red-contrib-wirenboard` при желании
  можно доставить через Palette Manager (нужен доступ в интернет).
- **За логином homeui.** Редактор слушает только loopback и отдаётся на
  **отдельном HTTPS-порту**, который nginx проксирует за стандартным логином
  Wiren Board (`auth_request`, **только админ** — Node-RED может выполнять
  произвольный код). Сессионная кука homeui привязана к хосту (без привязки к
  порту), поэтому доходит до порта; старый URL `/node-red/` оставлен как
  редирект на него. Компромисс: отдельный порт недоступен через туннель
  WB Cloud — доступ локальный/по LAN.
  Границей осознанно является именно *сетевой* гейт (in-app `adminAuth` нет):
  локально на контроллере `127.0.0.1:1880` — неаутентифицированный admin API,
  и любой локальный shell-аккаунт может управлять Node-RED.
- **Данные сохраняются при обновлениях.** Flows, учётные данные и любые
  установленные ноды лежат в `/mnt/data/wb-node-red` — на разделе, который
  переживает перепрошивку. `apt upgrade` меняет код и перезапускает сервис;
  ваши данные остаются.

## Требования

Гейт редактора рендерит **homeui** из декларации
`/etc/wb-homeui/gates.d/node-red.json`, которую ставит этот пакет. Нужен
`wb-mqtt-homeui` с механизмом service-gates (точный минимум версии закреплён в
`debian/control`). Без него пакет установится и сервис будет работать, но
**редактор останется недоступным**, пока homeui не обновится: декларация лежит
инертно и подхватывается автоматически при следующем старте homeui —
переустановка или `dpkg-reconfigure` не нужны.

TLS-сертификат отдельно готовить не нужно: homeui всегда держит файл
`/etc/ssl/sslip.pem` (до выпуска настоящего сертификата — просроченная заглушка,
браузер предупредит; предупреждение исчезает после получения серта).

## Как это устроено

| Что | Где |
|---|---|
| Код Node-RED | `/mnt/data/wb-node-red-runtime/node_modules/` (распаковывается из `.deb` при установке — держит дерево ~120 МБ вне тесного корня; перезаписывается при обновлении) |
| Шаблон настроек | `/usr/lib/wb-node-red/settings.js` (перезаписывается при обновлении) |
| Ваши переопределения настроек | `/mnt/data/wb-node-red/settings-user.js` (опционально, переживает обновления; мержится поверх шаблона — loopback-bind и `userDir` остаются закреплёнными) |
| Ваши flows / учётки / ноды | `/mnt/data/wb-node-red/` (заполняется, если пусто; сохраняется) |
| Сервис | `wb-node-red.service` → `node red.js`, пользователь `wb-node-red`, редактор на `127.0.0.1:1880` (httpAdminRoot `/`) |
| Гейт | `/etc/wb-homeui/gates.d/node-red.json` — декларация (`internalPort 1880`, `externalPort 21880`, `role admin`, `menu.title`), которую homeui рендерит в server-блок nginx на порту 21880 |
| Публичный доступ | `https://<homeui-host>:21880/` — admin-гейт homeui → `127.0.0.1:1880`; старый `/node-red/` 302-редиректит на `/open-node-red` |
| MQTT | дефолтный flow → `127.0.0.1:1883` |
| Меню homeui | «Node-RED» в разделе **Интеграции** — homeui генерирует пункт из `title` гейта (отдельный drop-in меню не нужен) |

Рантайм Node-RED **вендорится в `.deb` на этапе сборки**
(`npm ci --omit=dev` по `vendor/package.json`), поэтому установка не качает npm
и ничего не компилирует на контроллере. Единственный платформозависимый
компонент — опциональный биндинг `@node-rs/bcrypt` (Node-RED откатывается на
pure-JS `bcryptjs`) — вырезается после установки, а сборка падает, если в
дереве остаётся хоть один `*.node`-бинарник; именно это удерживает пакет
`Architecture: all`.
