## Краткая суть дизайна (детали — в design.md)

Три артефакта: пакет-хелпер `wb-docker-app` (общая логика, ставится один раз
как зависимость) + per-app пакеты `wb-<service>` (`Architecture: all`, несут
compose+конфиг+обвязку, `Depends: docker-ce, wb-docker-app`) + образы в
собственном registry WB (mirror ванильных / derived с вшитой WB-интеграцией).
Запуск — `docker compose` + шаблонный systemd-юнит. Данные на `/mnt/data`
(base в пакете + override у пользователя). Веб — port-for-all + reverse-proxy
с переиспользованием авторизации homeui (`auth_request`, роль admin). MQTT —
выделенная docker-сеть + listener mosquitto, настраивается хелпером один раз.

## Ключевые факты о контроллере (для PoC/валидации)

Кандидат: **`aat3d5fw`** (`wirenboard-aat3d5fw.local`), wb-2602 / wb7, уже на
репаке `docker-ce` 29.5.2, data-root `/mnt/data/docker/lib`, контейнеров нет.
Установлено через агента `wb-controller-ops` (в разговоре — «Миша»):

- **Авторизация homeui** — на уровне приложения через nginx `auth_request
  /auth/check` → `wb-homeui-backend` (unix-сокет, роли Admin/Operator/User).
  Статика `/` без гейта. → переиспользуемо для наших сервисов.
- **Drop-in для nginx**: `/etc/nginx/includes/default.wb.d/` (включается в
  server-block homeui; прецедент — интеграция Алисы). Пакетные include в
  `/usr/share/wb-mqtt-homeui/nginx/includes/` перезатираются на upgrade.
- **mosquitto**: `1883` на `0.0.0.0`, `allow_anonymous true`, ACL полный
  `readwrite #`; role-листенеры `18884/18885/18886` на loopback. На части
  контроллеров `1883` сужается до `127.0.0.1` (особенно после включения
  пароля на веб) — отсюда выбор выделенной docker-сети для MQTT.

## Открытые вопросы (требуют решения команды / инфры)

1. Можно ли хелперу трогать конфиг mosquitto (drop-in listener + один restart
   при установке)? Нужен апрув WB-команды.
2. Готова ли WB-registry под образы + отдельный CI-pipeline сборки образов
   (не `.deb`-Jenkins)?
3. Подсеть выделенной docker-сети (напр. `172.29.0.0/24`) — не пересекается ли
   с используемым в WB?
4. Политика портов (каждый сервис на своём порту за логином; аллокация во
   избежание коллизий)?
5. Валидация на реальном контроллере (auth_request, mosquitto reload/restart и
   bind на буте, связность контейнер→брокер) — через PoC.
6. Отдельный тикет/ветка под фреймворк (отдельно от репака)?

4. Снять открытые вопросы 1–4 с WB-команды/инфры до начала реализации.
